Anasemble now provides a production-shaped, restart-safe path from independently retained semantic evidence to a bounded, operator-approved recovery for its explicitly supported service and state profiles.

## Highlights

- **Durable operations:** Recovery jobs survive interruption through atomic records, leases, bounded retries, queue backpressure, audit chains, and derived metrics.
- **State recovery:** Filesystem, PostgreSQL 18, S3-compatible object storage, and Redis 8 Streams restore with verified rollback evidence and explicit consistency limits.
- **Isolated activation:** Plan-bound OCI artifacts run under zero-egress Docker isolation or health-gated Kubernetes activation with secret references and operation leases.
- **Operator lifecycle:** Rust-native installation, configuration migration, exact uninstallation, diagnostics, redacted support bundles, and a disaster runbook cover the supported arm64 profiles.
- **Retained evidence:** Local CI executes destructive state and activation drills, a 128-job sustained scheduler test, dependency checks, and the complete regression suite.

## Installation

Build with Rust 1.97.0 and locked offline dependencies, then install to a new owned prefix:

```text
cargo build --release --locked --offline
target/release/anasemble install /opt/anasemble-0.0.1
```

## Compatibility and claims

This candidate supports the exact protocols, arm64 platforms, backend versions, and trust boundaries in [Compatibility](../docs/COMPATIBILITY.md). It does not reconstruct arbitrary software, replace ordinary backups, support remote PostgreSQL or Redis transports, or prove a cross-backend distributed transaction. Independent reproduction and external security review are optional post-release assurance.
