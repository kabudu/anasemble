# Brand identity

## Status and version

Brand version `1.0.0` defines the owner-selected, maturity-neutral Semantic Fit
identity. Software maturity, support and assurance are separate overlays and must
never be added to the canonical mark, wordmark, tagline, palette or asset names.

## Platform

**Name:** Anasemble, a coined blend of Greek-derived “ana” (again/up) and
“assemble.” Capitalise only the initial A. Never split or respell the name.

**Category:** evidence-bound service reconstruction and disaster recovery.

**Purpose:** preserve an accountable path back to useful service function when
the original executable artifact is lost.

**Promise:** reconstruct only what surviving independent evidence can justify,
and refuse or roll back when the declared boundary is not satisfied.

**Tagline:** Regrow function from surviving meaning.

Principles are evidence before confidence, useful function rather than identical
artifacts, operator authority, explicit refusal and reversible activation.
Personality is rigorous, resilient, calm, precise and candid. Anti-traits are
magical, sentient, triumphant, absolute, playful-puzzle, militaristic and opaque.

## Semantic Fit construction

Three non-identical fragments converge around a Y-shaped negative-space
interface. Two interfaces fit; the east interface remains visibly open and is
bounded by a short amber bar. This says that useful function can be
assembled while genuine absence and uncertainty remain. It must never be closed
into a completed puzzle or animated as autonomous assembly.

Use the horizontal lockup by default, the stacked lockup when width is limited,
the symbol for avatars and favicons, the wordmark only when the product context
is already explicit, monochrome for one-colour production, reversed on dark
fields, and the simplified small symbol below 24 px. Minimum symbol size is 16
px; minimum horizontal lockup width is 120 px. Clear space on every side is one
eighth of symbol width. Do not rotate, skew, outline, add effects, substitute
colours, rearrange fragments, close the open join, or place the mark on noisy
imagery.

## Colour and accessibility

Canonical tokens live in `assets/brand/tokens`. Ink and paper are the primary
fields; mineral and teal distinguish surviving fragments; amber means controlled
absence, caution or operator attention. Refusal uses red, uncertainty uses ochre,
and exclusion uses slate. Every state also requires a label and distinct shape or
pattern. Never encode an outcome by colour alone. On dark fields use the reversed
asset. In forced-colour mode use system colours. Print and grayscale use the
monochrome mark and pattern-redundant chart key.

Inter is optional for product and documentation typography with system sans-serif
fallbacks. Technical evidence uses the platform monospace stack. No font binary
is vendored. Body text targets WCAG AA contrast; identity display elements are
not substitutes for accessible text labels.

## Icons, diagrams, charts and motion

Product/result icons use four redundant primitives: filled circle plus `PASS`,
bar plus `REFUSE`, triangle plus `UNCERTAIN`, and outlined square plus `EVIDENCE`.
Architecture diagrams use solid arrows for committed flow, dashed arrows for
candidate flow, blunt-ended lines for refused flow, and labelled boundaries for
trust changes. Charts must retain refusals, exclusions and uncertainty rather
than collapsing them into failure or omitting them. Use the source-controlled
diagram and chart keys.

Illustration should show bounded systems, retained evidence and operator control;
avoid people in crisis, destroyed cities, resurrection, magic, brains, mascots,
weapons and autonomous-agent imagery. Photography, if later used, must depict
real operators or infrastructure without dramatising disaster. Motion is
optional, never conveys state alone, and is removed under reduced-motion
preferences. Fragments must not self-assemble into a falsely complete artifact.

## Voice and messaging

Short description: “Anasemble reconstructs bounded service function from
independently surviving semantic evidence after total artifact loss.”

Technical description: “Anasemble collects authenticated independent semantic
fragments, synthesises a non-identical replacement within a declared service
contract, independently checks behaviour, restores supported state and activates
through an operator-approved rollback boundary.”

Developer voice is direct and procedural. Security voice starts with trust and
refusal boundaries. Buyer voice states the supported profile and operator burden.
Research voice separates established mechanisms from the candidate contribution.
Incident voice leads with state, consequence, safe next action and rollback.

Allowed qualified terms include `bounded`, `certified within the declared model`,
`supported profile`, `tested`, `experimental` and `operator-approved`. Prohibited
unqualified claims include `safe`, `perfect recovery`, `production-ready`,
`guaranteed`, `lossless`, `novel`, `autonomous`, `self-healing`, `code from
nothing` and `restores the original`.

## Maturity overlay

Release channel, version, support profile, production authorization, external
review and independent-reproduction status belong in notices, badges and the
`{MATURITY_OVERLAY}` field of channel templates. Changing those fields must not
change canonical sources or tokens. Current public copy must still reflect the
compatibility matrix and release authority.

## Governance and provenance

The repository owner holds product, brand and release approval. Engineering owns
deterministic exports and integration; security owns misleading assurance and
asset-sanitisation review; accessibility owns contrast and non-colour semantics;
research owns novelty and evidence wording; legal owns name, mark and licence
clearance. One person may hold several roles but each approval must remain
explicit at release.

Brand sources and tokens version independently from protocols. Change the major
brand version for mark or platform changes, minor for additive assets, and patch
for non-semantic corrections. Never overwrite a released manifest: archive it
with the release evidence and publish a migration note. The manifest records
creator/tool provenance, rights and digests. AI-assisted raster exploration was
used only to compare concepts; every canonical asset is an owned, reviewed SVG.

The preliminary name searches are not trademark clearance. No public or
commercial use is authorised until the separate legal and release gates pass.
