# Brand validation

The authoritative command is `cargo run --locked --offline --bin brand_assets --
check`. It verifies required source and exported assets, exact SHA-256 manifest
digests, safe SVG structure, accessible titles/descriptions, canonical maturity
separation, token values, and WCAG contrast pairs. `repo_check` invokes the same
library validation during local CI.

Human review on 2026-08-11 selected Semantic Fit from Semantic Weave, Recovery
Ledger and Continuity Aperture, then compared Missing Core, Semantic Fit,
Functional Mosaic and Evidence Assembly. Refinement compared Open Join, Bound
Interface and Assembled A. Open Join best preserved heterogeneous evidence,
genuine absence, small-size recognition and an enduring mechanism without
temporary maturity language.

The one-colour and 32-unit variants preserve the open interface without colour.
The diagram and chart templates pair colour with labels, shapes and patterns.
Light, dark, monochrome, print, forced-colour and reduced-motion behavior is
specified in tokens and the identity guide. Raster concepts are not release
assets. Cultural, trademark and user-comprehension review remain release gates;
they do not invalidate private productisation but constrain public use.

The bootstrap validator was also run with `--implementation-authorized`. Its
repository-wide Markdown pass reports the deliberate missing H1 in
`release/0.1.0-rc.1.md`: Anasemble's release renderer contract requires the body
to start with the user-visible outcome and rejects a duplicate Markdown title.
The authoritative repository checker enforces that stricter presentation rule.
This known validator-policy mismatch is not an asset or identity failure.
