# Release artifact contract

## First public candidate

The `v0.1.0-rc.1` release publishes source and installable command-line binaries,
not a hosted recovery service or package-registry release.

Required release outputs are:

| Artifact | Purpose | Boundary |
| --- | --- | --- |
| Annotated Git tag | Immutable source identity | Tag must resolve to the reviewed release commit |
| GitHub source archives | Source evaluation | Generated by GitHub from the tag |
| `anasemble-v0.1.0-rc.1-linux-aarch64.tar.gz` | Exact AL2023 arm64 command-line binary | Built and smoke-tested on the supported native profile |
| `anasemble-v0.1.0-rc.1-linux-x86_64.tar.gz` | Exact AL2023 x86_64 command-line binary | Built and smoke-tested on the supported native profile |
| `SHA256SUMS` | Download integrity | Covers every attached archive and provenance record |
| Per-target provenance JSON | Build identity and reproduction input | Records commit, target, toolchain, command, and artifact digest without secrets |
| crates.io package `anasemble` | Cargo installation and source package | Published only after `cargo package --locked` and exact package-content review |

Each binary archive contains the executable, `LICENSE`, `NOTICE`,
`TRADEMARKS.md`, the compatibility manifest, and an installation README. Release
validation extracts each archive in a clean directory, checks its digest,
executes `anasemble --help`, and exercises exact-prefix install and uninstall.

## Deliberately excluded

- No container image is published. The current OCI path produces recovery-plan
  artifacts, not a supported Anasemble control-plane deployment image.
- No macOS binary is attached to this first public release because the release
  contract does not yet define signing, notarisation, or a stable macOS archive.
- No SBOM or signature bundle is claimed until its generator, schema, signer,
  verification instructions, and key lifecycle are repository-owned and tested.

The crate is the existing Rust package, not a new crate split. Creating separate
library and CLI crates would add versioning and ownership complexity without a
proven consumer requirement. The release can add other artifact classes later without changing the source
opening or the supported recovery profiles.
